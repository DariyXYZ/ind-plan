# Промпт для Codex: библиотека планировок IND → база для генерации в IND Plan

## Роль и цель
Ты продолжаешь проект **IND Plan**: генератор планировок квартир для архитектурного бюро IND. Генерация идёт так: бриф (тип квартиры, контур, вход, стояки) → подбор похожего референса из библиотеки → подгонка под контур (`engine/fit.py`) → мебель кодом (`engine/furnish.py`) → Claude дорабатывает только остаток → валидатор (`engine/validator.py`) судит.

**Итоговая цель:** собрать из реальных проектов IND удобную и проверенную **базу планировок**, по которой генератор быстро находит подходящий референс и надёжно подгоняет его. Нужно не «больше JSON», а база, которой удобно пользоваться: единая схема, индекс для поиска, понятная статистика, проверки качества.

### 3. Единая схема и нормализация
- Свести всё в одну схему (версия `schema_version`), описать её в `pdf-library\SCHEMA.md` и в JSON Schema (`library.schema.json`) с валидацией.
- Нормализовать названия комнат в словарь ролей: hall, corridor, kg (кухня-гостиная), kitchen, living, bedroom, master, kids, wardrobe, bath, wc, laundry, storage, loggia… Исходное название сохранить в `name_src`.
- В `key` добавить признаки для поиска: число спален, есть ли гардеробная, мастер-с/у, постирочная, раздельная кухня, число с/у, ширина фасада, тип входа (hall/corridor/kg), положение стояков, `levels`.
- Поле качества: `geom: ok|approx`, `checks: {...}` с результатом каждой проверки, `source: {project, file, page, floor, section}` для трассировки до листа.
- Дедуп: одинаковый граф + площади ±3% + габарит ±200 мм = дубль. Хранить `count` (сколько раз встречается в проектах) — это сигнал «типовое решение IND».

## Правила работы
- Python, работа локально. X:\ — сетевой диск только для чтения: ничего туда не писать, не копировать PDF массово, пути хранить ссылками.
- Каждый новый экстрактор сначала проверяй на 2–3 листах с PNG-оверлеем и ручной сверкой графа, потом гоняй пачкой.
- Не ослаблять проверки ради количества. Лучше 50 точных квартир, чем 300 сомнительных. Приблизительная геометрия = `geom: approx`, площади брать из подписей.
- Не называть варианты «эталонными» или «хорошими»: архитекторы их ещё не оценивали. В `src` писать «проект IND (не оценено)».
- Старые результаты (`out_barkhatnaya`, `out_fotieva`, `out_all`) не перетирать: новое класть в новые папки, библиотеку собирать скриптом.
- Коммитить небольшими шагами, понятные сообщения на русском.
